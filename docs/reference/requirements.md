근처 편의점 4사의 품목 · 가격을 내 결제 수단 기준 최종 결제액으로 찾는 서비스예요.

- `(안)` = 제안값이며 정하는 사람이 바꿀 수 있어요.
- 구분: **실제** = 실제 API · 실제 데이터 / **목업** = 예시 데이터

## 2. 최종 결제액 계산 규칙 (FR-04)

입력 = 상품 1개 · 필요한 개수 `qty` · 사용자 결제 수단 `wallet`. 순서대로 적용해요.

| 순서 | 단계 | 규칙 |
| --- | --- | --- |
| 1 | 행사 | N+1 행사면 `paidQty` = "`paidQty` + ⌊`paidQty` ÷ N⌋ ≥ `qty`"를 만족하는 가장 작은 수. 받는 개수 `receivedQty` = `paidQty` + ⌊`paidQty` ÷ N⌋. `eventPrice` = `listPrice` × `paidQty`. 행사 없으면 `paidQty` = `qty` |
| 2 | 통신사 할인 | 사용자 통신사 · 등급 · 브랜드가 맞는 규칙 1개. 행사 상품이고 `stackWithEvent` = false면 적용하지 않는다. 할인액 = ⌊`eventPrice` × `rate`⌋, `maxAmount`가 있으면 그 금액까지 |
| 3 | 결제 할인 | 등록한 카드 · 페이 규칙 중 `kind` = DISCOUNT이고 브랜드가 맞는 것에서 **할인액이 가장 큰 1개**(결제는 한 수단으로 한다). 기준 금액 = 2단계 뒤 금액. `requiresPrevMonth` = true인데 사용자가 전월 실적 미충족이면 제외. `minPayAmount` 미만이면 제외 |
| 4 | 적립 | `kind` = POINT인 규칙 중 가장 큰 1개. **결제액에서 빼지 않고** `pointAmount`로 따로 표시 |
| 결과 | `finalPrice` | `eventPrice` − 통신사 할인 − 결제 할인 |

- 원 단위 미만은 버린다(안)
- 정렬: `finalPrice` 오름차순 → 같으면 `distanceM` 오름차순. 재고 `OUT` 행은 맨 아래(안)

### 예시

펩시콜라 600ml, GS25, 1+1, 정가 2,500원, `qty` = 1, KT VIP

| 단계 | 값 |
| --- | --- |
| 행사 | `paidQty` 1, `receivedQty` 2, `eventPrice` 2,500 |
| 통신사 | GS25는 행사 상품 중복 불가 → 0 |
| 결과 | `finalPrice` 2,500, "1개 더 받음" 표시 |

## 3. 재고 더미 규칙 (FR-10)

| 항목 | 값 |
| --- | --- |
| 값 | `IN_STOCK`(있음) · `LOW`(적음) · `OUT`(없음) |
| 만드는 법(안) | `storeId + ":" + productId` 문자열 해시를 10으로 나눈 나머지(음수면 양수로). 0 ~ 5 = `IN_STOCK`, 6 ~ 8 = `LOW`, 9 = `OUT` |
| 저장 | 저장하지 않는다. 요청 때마다 같은 규칙으로 계산 |
| 화면 | 재고 옆에 "예시 데이터" |
