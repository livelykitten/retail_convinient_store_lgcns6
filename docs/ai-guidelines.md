# AI 사용 규칙

AI 도구(Claude Code, Codex, Cursor, ChatGPT 등)를 쓸 때 사람과 AI가 함께 지키는 규칙이에요. 저장소 루트의 `AGENTS.md` · `CLAUDE.md`는 AI 도구가 자동으로 읽는 입구이고, 자세한 내용은 이 문서에 있어요.

## 원칙

1. **AI에게 맡겨도 되는 것**: 엔티티 · DTO · 컨트롤러 · 테스트의 틀, 반복 코드, 이슈 · 커밋 메시지 · PR 본문 초안
2. **사람이 정하는 것**: 계산 규칙, API 계약(경로 · 필드 · enum · 오류 코드). **필드 이름은 명세에서 복사해요.** AI가 지은 이름을 그대로 쓰지 않아요.
3. **실행은 사람이 해요.** 저장소와 GitHub에 흔적을 남기는 동작(커밋, push, PR, 승인, 병합)은 사람이 직접 해요. 그래야 누가 무엇을 확인하고 올렸는지가 분명해요.

## 할 수 있는 것과 없는 것

| 단계 | AI가 해도 되는 것 | AI가 하면 안 되는 것 (사람이 함) |
| --- | --- | --- |
| 1. 이슈 | 템플릿에 맞춘 본문 초안 작성 | 이슈 생성 · 수정 · 닫기, 라벨 · 담당자 지정, 칸반 이동 |
| 2. 브랜치 | 규칙에 맞는 이름 제안 | 브랜치 생성 · 전환 · 삭제 |
| 3. 작업 | 코드 · 테스트 · 설정 · 문서 파일 작성과 수정, 테스트 · 빌드 실행, 커밋 메시지 초안 작성 | `git add`, `git commit`, `git push`, `git merge`, `git rebase`, `git reset` |
| 4. PR | 제목 · 본문 초안 작성 | PR 생성 · 수정 · 닫기, 리뷰어 지정 |
| 5. 리뷰 | 리뷰어가 요청하면 로컬에서 diff 요약, 문제 후보 찾기 | 리뷰 의견 게시, Approve · Request changes |
| 6. 병합 | — | 병합, 되돌리기(Revert) |

읽기만 하는 명령은 써도 돼요: `git status`, `git diff`, `git log`, `git show`.

## 막는 방법

규칙 문서만으로는 실수를 다 막지 못해서 두 겹으로 막아요.

| 겹 | 내용 | 막는 범위 |
| --- | --- | --- |
| 1. 규칙 문서 | `AGENTS.md`, `CLAUDE.md`, 이 문서 | 모든 AI 도구 (지시로) |
| 2. 저장소 설정 | `main` 브랜치 보호, 승인 1명 필수 ([CONTRIBUTING.md](CONTRIBUTING.md#저장소-설정-백엔드-리드가-처음에-한-번-안)) | 모든 도구와 사람 (강제로) |

- AI 도구에서 git · GitHub 명령은 자동 실행하지 않도록 설정해요(명령마다 확인 받기).
- GitHub MCP 서버나 `gh`를 AI 도구에 연결했다면, 쓰기 권한이 없는 토큰을 쓰거나 쓰기 도구를 꺼요.

## AI에게 일을 시킬 때

### 시작 전에 알려 줄 것

- 이슈 번호와 완료 기준
- 담당 모듈 (고쳐도 되는 패키지)
- 관련 스펙 (FR 번호, [reference/](reference/requirements.md)의 절, [design.md](design.md)의 인터페이스)

```
#15 작업이야. quote 패키지만 고쳐.
docs/reference/requirements.md 2절 규칙대로 4단계 계산을 만들어 줘.
필드 이름은 docs/reference/api-spec.md 5절에서 그대로 써.
검증 예시는 내가 줄게. 그걸로 단위 테스트도 만들어 줘.
끝나면 커밋 메시지 초안과 PR 본문 초안을 써 줘.
```

### AI가 지킬 것

- **담당 모듈 패키지 밖을 고치지 않아요.** 꼭 필요하면 고치기 전에 사람에게 묻고, PR 본문 초안의 메모에 적어요.
- **스펙을 추측하지 않아요.** 경로 · 필드 · enum · 계산 규칙은 [reference/](reference/requirements.md)에서 찾아요. 없으면 만들지 말고 "확인 필요"로 남겨요.
- **계산 규칙을 바꾸거나 "더 나은" 규칙을 제안해서 코드에 넣지 않아요.** 규칙이 모호하면 멈추고 질문 목록을 만들어요.
- **스펙과 다르게 만들어야 하면 멈추고 알려요.** 스펙 변경 이슈 초안을 써 주는 것까지가 AI의 일이에요.
- **진행 상태를 문서로 만들지 않아요.** 작업 현황은 이슈와 칸반에 있어요. TODO.md, 진행상황.md 같은 파일을 만들지 않아요.
- **실행 확인 없이 "완료"라고 하지 않아요.** 테스트나 빌드를 돌렸으면 결과를 그대로, 못 돌렸으면 못 돌렸다고 말해요.
- **비밀 값을 읽거나 쓰지 않아요.** 카카오 · AI 키를 코드나 설정 파일에 넣지 않아요.
- **범위 밖 기능을 만들지 않아요.** 로그인, 결제, 실시간 가격 수집, 요청하지 않은 리팩터링을 끼워 넣지 않아요.
- 판단이 갈린 곳, 확신이 없는 곳을 PR 본문 초안의 메모에 `(확인 요망)`으로 적어요.

### 사람이 할 것

- AI가 쓴 코드는 **커밋하기 전에 diff를 직접 읽어요.** 설명할 수 없는 코드는 커밋하지 않아요.
- AI가 만든 필드 이름 · enum 값이 명세와 같은지 확인해요.
- AI가 쓴 이슈 · PR 본문은 사실과 맞는지 확인한 뒤 올려요. 특히 "확인 방법"과 "테스트 결과"는 직접 돌려 본 결과여야 해요.
- PR 본문의 메모에 AI에게 무엇을 시켰는지 한 줄 적어요. 예) `계산 클래스 틀과 테스트를 Claude Code로 작성 후 수정`

## 초안 형식

| 초안 | 형식 |
| --- | --- |
| 이슈 | `.github/ISSUE_TEMPLATE/`의 해당 템플릿 항목 순서대로 |
| 브랜치 이름 | `<타입>/<FR번호 또는 이슈번호>-<짧은-설명>` |
| 커밋 메시지 | `<타입>(<범위>): <제목>` + 본문 + `Refs: #번호` |
| PR | `.github/pull_request_template.md` 항목 순서대로, [CONTRIBUTING.md](CONTRIBUTING.md#pr-본문-쓰는-법)의 문체 |
| 리뷰 의견 | `[필수]` · `[제안]` · `[질문]` 머리말, 파일과 줄 번호 |

초안은 대화창에 써요. 저장소에 초안 파일을 만들지 않아요.
